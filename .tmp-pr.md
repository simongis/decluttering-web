## What

Lets a signed-in user delete stale or large hosted feature layers from Review, with their own ArcGIS Online account. **Off unless the build sets `VITE_DELETING=on`**: with it off, the app, the demo and all its wording stay exactly as they were ("never deletes").

Design: [`docs/adr/0016-deleting-layers.md`](../blob/feat/delete-stale-items/docs/adr/0016-deleting-layers.md) · User docs: README › *Deleting layers* · Manual test plan: [`docs/testing/deleting.md`](../blob/feat/delete-stale-items/docs/testing/deleting.md)

## How it works for the user

- **Select on the chart:** drag a rectangle over the Review chart; every layer inside is added to the delete selection, whether or not it meets the rule. Each rectangle adds, and says how many it added and how many it left out because the user can't delete them. Selected dots get a red ring.
- **Click a dot:** a small menu offers **View item** (new tab), **Add to / Remove from selection** and **Delete…**. Keyboard: arrows, Enter, Escape. With deleting off, and on the scan screen, a click opens the item as before.
- **On the list:** each row has *Select to delete* and *Delete…*; a bar above the list has Select all, the count and storage selected (and how many are outside the list), Clear and Delete selected. Also Delete in the item panel. The same count and buttons sit above the chart.
- **The delete bar always says where it stands:** ready, waiting for maps and apps, scan stopped, no privilege, or nothing on the list (then it points to the chart).
- **Confirm dialog:** each layer with owner, size, views and used-by warnings, a **Remove** per layer, the account name, and a typed word (`DELETE` / `BORRAR`). Stop between families.
- **Download report (CSV)** after a run: one row per layer (when, org, who, owner, size, views, result, reason). ArcGIS Online doesn't tell owners and the app has no backend, so this is the record.
- **Version line in the header:** `v1.4.0-dev.N · <commit> · deleting on|off`.

## Safety

- **Default deny:** `VITE_DELETING` unset or anything but `on` → no delete UI and no remover can be built (`src/auth/deleting.ts`). The Pages workflow passes the repository variable `VITE_DELETING`, unset by default.
- **Privileges:** `portal:admin:deleteItems` → anyone's layers; `portal:user:createItem` → own layers; otherwise none. ArcGIS Online still enforces its own rules.
- **Own allow-list** (`src/remove/guard.ts`): only an item read and `content/users/{owner}/[{folder}/]items/{id}/delete` (POST), only for owners the user may delete, and no parameter beyond `f`, so `permanentDelete` can never be sent. Scan and notifier guards unchanged.
- **Check, then act:** each family (views first, then source) is re-read just before deleting and skipped if protected, no longer a hosted feature layer, or owned by someone else. A delete counts only on `success: true`.
- **Only on a finished scan:** disabled while maps and apps are read, after a stopped scan, or during a refresh.
- **CSV report:** built in the browser, nothing sent; formula-like text is defused.

## Also in this PR

- `npm run dev` always uses port 5173 and fails if it is taken, instead of moving to 5174, where sign-in fails with *Invalid redirect_uri* (the OAuth redirect is registered for 5173).
- The dev simulator takes `role=member|viewer` to exercise My items and the no-privilege case.

- Set the release number in `src/version.ts` (`1.4.0-dev.N` → `1.4.0`) when merging.
- **Squash and merge** is suggested: the branch has many small commits from iterating on the UI.
- Not included: restoring from the recycle bin, unprotecting items, deleting maps/apps or non-hosted items, writing deletes to the shared nudge log table (the CSV stands in; changing what that table holds is a project decision), emailing owners about deletes, a rectangle on touch screens.
